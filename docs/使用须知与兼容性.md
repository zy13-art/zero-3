# 使用须知与兼容性说明

适用于 zero-3 / Codex Kurumi Intro 1.4.0。

## 使用前先了解

这是独立的 Windows 启动动画播放器。双击本项目的快捷方式后，先显示不透明全屏窗口，再异步启动官方 Codex。它不替换 Codex 安装目录里的资源，也不会拦截所有官方入口；直接打开官方程序、任务栏中未修改的图标或其他快捷方式，不一定经过本动画。

四段影片的媒体时长均为 **8 秒**，每次随机选一段并避免连续重复。前3秒为流光线稿入场，前6秒为主体剪辑，6～8秒为水波与逐渐模糊，7～8秒拉远退出。播放器打开和解码也需要时间，所以“双击到动画退出”的总耗时可能超过8秒。

**Codex 启动耗时与影片时长是两回事。** 如果客户端8秒内就绪，动画结束后显示页面；如果受硬盘、系统负载、更新或网络等因素影响仍未就绪，动画照常结束，客户端继续启动。此时可能暂时看到桌面或应用加载画面，不代表动画丢失，也不保证8秒内一定可以聊天。

## 兼容范围

| 项目 | 说明 |
| --- | --- |
| 系统 | 面向 Windows 10/11 **x64**。提供的原生播放器及构建脚本固定为x64；macOS、Linux不适用，ARM64未验证。 |
| 客户端 | 适配微软商店安装的官方 Codex。当前进程文件可能名为 `ChatGPT.exe`，启动脚本按官方安装路径识别。其他打包形式、路径和后续客户端变更需要另行适配。 |
| 播放运行库 | 使用系统WPF/.NET Framework 4.x及Windows视频解码组件，建议保持系统组件完整。播放不需要Node、Python或FFmpeg。 |
| 默认影片 | 3840×2160、60fps、H.264、AAC。优先使用支持4K H.264硬件解码的显卡和驱动；显卡、核显切换及系统负载会影响流畅度。 |
| 存档影片 | `masters/` 为7680×4320、90fps、HEVC，不接入默认启动入口。该规格资源占用明显更高，需要支持对应HEVC解码的播放器和硬件。 |
| 实际画质 | 原始素材为540p/720p、30fps，经光流插帧、调色和放大。4K/8K是输出规格，不能等同于原生高分辨率细节。没有交付16K版本。 |
| 显示范围 | 置顶全屏覆盖鼠标所在的显示器；没有承诺多个显示器同时覆盖。不同缩放比例、多屏布局和显示模式需要本机确认。 |
| 文件位置 | 请完整解压/克隆到普通可写目录。播放器需要在自身目录写入日志、随机选择记录和快捷方式备份，不建议放在只读目录。 |
| 声音 | 播放器音量75%，同时受Windows系统和应用音量控制。Zi-O钟声只敲一次，保持原音自然衰减，不做循环或拉长。 |

本机版本已由使用者重启试用，当前反馈正常。这不代表已完成所有电脑、系统版本、驱动和多屏组合的兼容测试。低性能设备优先降低影片分辨率/帧率；不要把8K90直接替换为默认启动影片来判断软件是否兼容。

## 进程与重复启动

同一份播放器目录使用系统互斥锁，连续双击时只保留一份动画。原有Codex会话会保留，脚本不会为了播放动画而强制关闭它。

以下情况仍可能产生重复窗口、启动延迟或焦点差异：同时使用官方图标和动画图标；同时运行多个不同目录中的播放器副本；保留旧版启动脚本、壁纸监听器或其他启动管理工具。建议只保留一个正式入口，升级后不要同时运行新旧两套启动器。

如果Codex尚未就绪，动画结束后不一定立刻取得客户端窗口焦点。被最小化或位于其他显示器的客户端，也需要结合自己的桌面布局确认。不要用反复连点代替等待实际进程启动。

## 配置、壁纸和本机连接

公开配置中的 `codexExecutable` 与 `wallpaperProject` 默认留空，不包含制作者个人路径。启动脚本会尝试从商店安装信息和官方进程发现客户端；发现失败时，按本机实际安装位置填写 `codexExecutable`，不要复制别人的版本号路径。

壁纸项目为可选外部依赖，并未打包进本仓库。如已安装兼容的 CodexChatWallpaper，可将其目录填入 `wallpaperProject`；缺失时原生动画仍可运行。

后台启动保留该集成方案使用的 `%LOCALAPPDATA%\CodexChatWallpaper\profile` 目录和 `127.0.0.1:9335` 本机调试连接。这个资料目录可能与官方普通入口使用的不同。**不要把该目录、登录资料或日志提交到仓库。** 同机程序可连接调试端口控制客户端；完全退出该实例并从官方普通入口打开，才能停止这个实例的调试连接。动画结束本身不会关闭该连接。

## 排查与恢复

| 现象 | 先检查 |
| --- | --- |
| 完全不出现动画 | 确认点击的是安装脚本修改过的快捷方式；检查同目录存在 `CodexKurumiIntro.exe`、`config.json` 和 `films/` 四段影片。 |
| 黑屏、无法解码或卡顿 | 查看 `native-startup.log` 的 `MediaOpened` / `MediaFailed` / `PlaybackTimeout`；检查系统视频解码组件、显卡驱动及当前负载。播放器遇到失败/超时会释放遮罩。 |
| 动画结束，客户端还没出现 | 查看 `bootstrap.log`；确认官方客户端已安装、启动路径有效，并等待实际启动完成。八秒影片不会等待聊天页面。 |
| 聊天页先出现，后来又播一次 | 检查是否仍在调用旧的 `intro.mjs` 覆盖层、旧快捷方式或其他自动启动入口；正常入口应直接指向原生EXE。 |
| 反复弹出多份动画 | 关闭多余的播放器副本和旧入口；同目录互斥不等于跨所有目录、所有启动工具的全局拦截。 |
| 没有声音 | 检查系统静音、应用音量和输出设备；钟声出现时间按四段各自钟体显现节点设置，不是固定开头播放。 |
| 想退出动画 | 按Esc或点击右上角“跳过”。客户端后台启动仍会继续。 |
| 想恢复原来的桌面入口 | 运行 `Restore-DesktopShortcut.ps1`。安装时生成的 `ChatGPT-original.lnk` 必须保留；脚本会检查当前快捷方式仍属于本项目。 |

日志用于本机排查，可能含本机文件路径与启动环境信息。提交问题时只提供有关事件和必要配置，并隐去个人路径；仓库已通过 `.gitignore` 排除日志、选择历史和原始快捷方式备份。
