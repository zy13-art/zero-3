# 使用须知与兼容性

适用于 zero-3 **1.5.0**。请完整解压到普通可写目录，不要直接在ZIP中运行。

## 启动方式和八秒时长

默认由 `CodexKurumiIntro.exe` 在后台启动官方Codex和Node控制器。确认本机调试监听属于当前会话的官方客户端后，控制器在唯一可见主窗口的文档可用时添加不透明遮罩，随后读取/传输影片并等待首帧。它不再等待聊天主界面、页面加载完成或壁纸助手完成。

这仍是**临时窗口内动画层**，不是官方原生启动资源替换。它不修改官方安装文件、聊天内容或壁纸工程。官方图标、商店入口、客户端内重启、更新重启不一定经过本项目。

影片媒体时长8秒：前3秒线稿、前6秒主体，6～8秒水波渐糊，7～8秒拉远。等待主文档、影片传输和解码属于额外开销。“双击到动画结束”可能超过8秒，也不承诺8秒内就能聊天。由于无法接管官方窗口创建过程，首次窗口绘制前完全无聊天闪帧并未得到保证。

| 显示范围 | 在所选Codex主窗口内等比完整显示，比例不同时有黑边；不全屏遮住其他应用或其他显示器。隐藏或Mini窗口不注入；多个主页面同时存在时拒绝猜测目标。 |

## 快捷方式与重复启动

桌面安装脚本默认修改现有ChatGPT.lnk，其他名称用-ShortcutPath。对于开始菜单、任务栏或仍保留官方应用身份的旧链接，使用Repair-LaunchShortcuts.ps1显式指定路径。它保存原件后创建新链接，保留图标并去掉旧官方AppUserModelID；拒绝覆盖其他程序的同名入口。

Windows任务栏上已运行程序的按钮通常只是聚焦窗口，不是重新执行启动器。已有固定项仍可能绑定官方应用；应重新固定已修正的桌面或开始菜单快捷方式。修复链接文件不等于自动接管所有商店应用图标或所有固定项。

同一目录的C#互斥与Node启动租约防止重叠播放。不同目录的副本、旧脚本、其他壁纸监听器及官方入口混用，仍可能产生焦点差异或额外进程。建议使用一份正式目录和一套已确认的入口。不会为了测试动画强制结束正在使用的客户端。

## 本机连接、账户与壁纸

公开配置的codexExecutable、wallpaperProject、nodeExecutable都留空，不包含制作者路径。官方客户端和Node路径可自动查找；可选CodexChatWallpaper为外部项目，未打包在仓库中。缺少壁纸项目不会阻止动画，动画也不会等待壁纸助手完成。

启动方案沿用 `%LOCALAPPDATA%\CodexChatWallpaper\profile` 与 `127.0.0.1:9335`。此资料目录可能与官方普通入口不同。不要上传资料目录、登录文件或本机日志。同机程序可能连接该调试端口并控制已登录客户端；动画结束、恢复外观或退出启动器本身不会关闭它，需正常完全退出该实例，再从原官方入口启动。

已有未打开本机调试连接的Codex会话会保留；控制器有界等待后退出，不杀进程或自动重启。首次测试应保存工作、正常完全退出，再从本项目入口启动。监听归属不明、非本机会话、非loopback或多个主页面时拒绝注入。

## 排查与恢复

| 现象 | 检查项 |
| --- | --- |
| 完全不出现 | 确认入口目标是本包EXE；检查config、四片影片、Node是否存在；确认不是只点击了已运行的任务栏窗口按钮。 |
| 找不到Node | 配置nodeExecutable为实际node.exe绝对路径，或安装Node并重开入口以更新PATH。 |
| 一直显示聊天，没有动画 | 查intro.log与native-startup.log；可能绕过入口、已有实例无调试端口，或主窗口/监听校验未通过。 |
| 聊天短暂闪出后才遮盖 | 早期挂载仍依赖官方调试监听和主文档，不能保证第一次paint前接管；提交日志中的遮罩/首帧时间，隐去个人信息。 |
| 黑幕、解码失败或卡住 | 查intro.log。接收/解码/播放分别有超时，失败移除本项目层。--native模式查MediaRequested、MediaOpened、MediaFailed、PlaybackTimeout。 |
| 重复动画 | 排查不同目录副本、旧自动启动工具和新旧入口混用；窗口内失败不会自动再弹独立动画。 |
| 最后两秒糊 | 是既定水波模糊/拉远效果。中段清晰度受原540p/720p素材限制。 |
| 没声音 | 检查系统/应用音量；浏览器隔离预览默认静音，正式片保留AAC和钟声。 |
| 退出动画 | Esc或右上角跳过；只清理自己的层和回调，后台客户端继续运行。 |
| 恢复桌面入口 | 运行Restore-DesktopShortcut.ps1，保留安装时生成的ChatGPT-original.lnk。 |
| 恢复显式修复的入口 | 用Repair-LaunchShortcuts.ps1指定原路径并加-Restore，依赖本机shortcut-backups/原件。 |

公开仓库不包含任何人的原始快捷方式、备份、日志、选择历史、账户资料或认证配置。本机自用版的整体回退脚本依赖私人备份，也不作为公开恢复工具打包。需要退回旧算法或旧播放器时，使用1.4.0历史提交并重新接好自己的入口，不混合两版文件。

## 清晰度与验证边界

本次1.6.0从540p/720p原始素材重新制作：animevideov3 x4/x3超分到4K，RIFE v4.6 UHD生成90fps源时间网格，再按既有曲线输出4K60、8秒。优先保证正式启动版的兼容性和流畅度，90fps仅为制作中间网格，实际播放仍为60fps。前3秒入场、前6秒运镜震动、末2秒水波渐糊和末秒拉远保留，原AAC内容与时间戳逐包一致。

超分和补帧可能产生细节或运动伪影，不能恢复原片没有的真实信息，也不能保证身份、颜色或运动绝对零误差。使用现有动漫设计，不添加真人皮肤纹理或重新布光。画面中有意设置的震动、光晕和收尾模糊不会因超分而消失。

docs/validation-v1.6.0.json包含四片SHA、全480帧解码结果、音频包及曲线映射核验。当前版本通过本机文件核验和启动器只读检查；本次尚未进行官方客户端完整冷启动实测。历史启动器测试不等于不同设备上的时序保证。显卡驱动、4K硬件解码、系统负载、既有实例与官方客户端更新仍可能影响首次显示和流畅度。

masters/仍为1.4.0的历史8K90存档，不是本次4K超分的输入或核验母版。需要回退时使用对应历史提交的完整目录，再接好自己的入口；本机私有回退脚本和备份不上传。
